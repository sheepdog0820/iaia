## 固定する範囲

`--include-billing-prerequisites`を明示した場合だけ、次の順序の未適用計画を許可する。途中まで適用済みの短い計画、別アプリの未適用分、逆方向、未知の適用履歴がある場合は適用前に停止する。

1. accounts.0065_stripe_billing_requests
2. accounts.0066_stripe_invoice_states
3. accounts.0067_billing_email_delivery
4. accounts.0068_merge_skill_bonus_into_other

0065〜0067は、新しいStripe作成要求・請求状態・課金メール配送テーブルを作る。0068は両版の`bonus_points`を`other_points`へ合算し、旧bonusを0にする。料金・権限の業務仕様、Stripeリクエスト、メール送信、依存関係や移行ファイルの内容は変更しない。

`--apply`・承認済みホスト/DB名も必須で、実接続の`current_database()`を照合する。オプションを省略した既存の0068限定モードとその結果形式は維持する。

## トランザクション内の確認

4件は同じPostgreSQLトランザクション内で適用する。移行履歴・両版の技能に加え、既存の購読/課金監査テーブルへの書き込みをロックする。これは運用上の全書き込み停止を代替しない。ロック待ちは2秒、各SQLは10秒の制限を設ける。

技能は全物理列・全行を適用前後で比較し、許可する差はbonus/otherの合算だけ。合算前にint32範囲を検査する。既存の購読・課金監査も、履歴モデルにない追加列を含めて全物理列・全行を比較する。行データはメモリ内でハッシュ化し、出力しない。

適用後には、新しい3テーブルが空であることと、4件すべての適用記録を確認する。比較不一致・途中の例外・記録欠落なら、技能データ・既存課金データ・新規DDL・移行履歴を同じトランザクションで取り消す。

COMMIT応答が失われた場合は、すでに適用済みの可能性があるため「取り消した」と表示しない。接続・SQL・行データを含み得る例外本文を表示せず、読み取りで適用状態を再確認するよう案内する。自動的に再実行しない。
