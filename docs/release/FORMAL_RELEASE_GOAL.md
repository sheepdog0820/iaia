# タブレノ正式公開の目標

策定日: 2026-09-05
状態: 目標設定済み。現在の実装・検証証跡の棚卸しは未完了。

## 目的

クトゥルフ神話TRPGのGM・PLが、日程調整から参加者・シナリオ・キャラクターの準備、秘匿HOの配布、プレイ履歴の記録までを安心して行えるサービスを提供する。

有料プランと外部連携を含む正式公開を目指すことは、ユーザーが明示的に選択済み。無料β公開に縮小して目標達成としない。

## 達成する状態

公開対象の機能を完成させ、主要操作、情報保護、性能、課金、外部連携、障害復旧の検証証拠を揃え、人間が本番リリースの可否を判断できる状態にする。既知の重大不具合や未確認の必須項目を残して完了としない。

本番リリース準備完了と、本番反映・公開後の確認完了は別に記録する。公開操作には別途承認が必要であり、この目標は本番操作や支出の包括承認ではない。

## 公開対象の基準案

以下は現行仕様を出発点とする作業範囲。詳細は実装と照合して受け入れ条件を作成する。未検証を理由に機能を黙って公開対象から外さない。

| 領域 | 対象と確認内容 |
| --- | --- |
| 中核機能 | アカウント、グループ、招待・ゲスト参加、日程調整、セッション、シナリオ、CoC 6版/7版キャラクター、HO・添付、画像、プレイ履歴の一連の利用 |
| 有料プラン | 料金と無料/有料の機能差、月額・年額の申込、利用権限付与、更新、解約、支払失敗と回復、Webhook重複・順序変動、返金・異議の処理、監査ログ、退会との整合性 |
| 外部認証 | Google・Discord・Xのログイン、アカウント連携、取消・失敗時の動作。公開するプロバイダーごとに実認可で確認 |
| 外部連携 | Google Calendar片方向同期、Google Sheets出力、Discord通知、ICS購読、ココフォリア向け出力。実サービスまたは受け取り側で確認し、権限失効・失敗・再試行・重複・解除を対象にする |
| 情報保護 | GM/PL/所有者/部外者ごとの権限、秘匿HO・GMメモ・個人情報、直URL/API/添付/共有リンク/通知/外部出力の漏えい防止 |
| 操作性・性能 | PC・スマートフォンの主要操作、入力エラーからの復帰、想定利用規模での応答・同時利用・アップロード |
| 運用 | 本番設定、監視・通知、バックアップ取得と復元、ロールバック、問い合わせ、規約・プライバシー・商取引表示、障害対応 |

ネイティブアプリ、AI分析、新しい未合意の外部サービス対応はこの目標から自動的には追加しない。

## 公開判定の条件

- 公開対象機能と受け入れ条件が一覧化され、現行コミットに対するテスト・CI・ステージングの結果を追跡できる。
- 主要利用フローが成立し、情報漏えい、データ消失、課金誤り、主要操作の停止につながる既知の重大不具合がない。
- 課金はStripeのテスト環境で実イベントを使い、一連の契約・権限変化と監査記録を確認する。モックのみの成功で外部検証完了としない。本番設定の確認と実課金操作は区別する。
- 有料正式公開の課金ゲートは `python manage.py billing_release_gate --require-paid-checkout --verification-record <検証記録>` を使用する。Checkout無効時の通常CIゲート成功を正式公開の合格証拠にしない。記録内容は実Stripeとアプリの状態に別途照合する。
- 外部連携は公開対象ごとに正常系と失敗・復旧を確認する。利用者に必要な外部サービス側の公開許可・設定も確認する。
- 性能の合否は、想定ユーザー数・同時利用・データ量と許容応答時間を定めて評価する。未測定を合格扱いしない。
- バックアップからの復元、監視通知、復旧手順を承認された環境・宛先で実証する。
- 料金、利用権限、運営者情報、保存期間、問い合わせ先など、人間が決める事項が確定している。
- 未解決事項は影響・回避策・担当・公開可否への影響とともに記録し、重大でない残リスクの受容は人間が判断する。

## 実施順序

1. 現行コード、GitHub Issues、CI、既存仕様・検証記録を照合し、「未実装」「実装済み・未検証」「検証済み」「人間の判断待ち」を分類する。
2. 公開対象ごとの受け入れ条件と証跡表を作成し、重大な欠陥・機能不足から修正する。
3. 自動テスト、ブラウザ確認、課金・連携の外部検証を進める。承認が必要な設定は具体的な変更案を準備してまとめて依頼する。
4. 性能と運用復旧を検証し、リリース候補コミット・移行手順・復旧手順を固定する。
5. 本番Go/No-Go資料を提出する。承認後に本番反映と公開後スモークテストを別工程として実施する。

## 判断事項と現時点の制約

- 人間の判断が必要: 最終的な料金・無料/有料の機能差、初期利用規模と費用上限、公開時期、保存方針と対外的な約束。Codexが現行案と推奨案を整理してから判断を求める。
- GitHub CLIは2026-09-05時点で未認証だが、GitHub連携経由の読み取りは成功。未完了Issue検索では画面改善の #1 を確認した。課題アーカイブの課金・運用残項目と現在のIssuesを同一視せず、コード・実環境の証跡を追加で照合する。
- 既存文書のテスト成功・実装完了記録は過去の証拠として扱い、現在の正式公開可否は未判定。
- 実行権限・承認境界はルートの [AGENTS.md](../../AGENTS.md) に従う。
