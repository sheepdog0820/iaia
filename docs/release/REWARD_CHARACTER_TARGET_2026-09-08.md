# 報酬再反映時のキャラクター照合

## 問題と変更

一度報酬を成長記録へ反映した後、セッション参加者のキャラクターを差し替えて再反映すると、以前のキャラクターの成長記録が更新されていた。現在の参加キャラクターと更新対象が一致しないため、誤った上書きを防ぐ。

既存の成長記録をロックして読み込んだ後、現在の参加キャラクターIDと照合する。一致しなければ日本語の400応答を返し、旧成長記録・反映日時・反映先を保持する。新キャラクターへの成長記録の自動複製や移動は行わない。元のキャラクターに戻した場合は、同じ成長記録への再反映が従来どおり可能。

参加キャラクター自体の変更を禁止する仕様ではない。別キャラクターへの反映済み報酬の移行機能が必要な場合は、旧記録の取り扱い・重複付与の防止を含めて別途設計する。

## 検証範囲

`schedules.test_session_rewards` は最終5件成功（13.163秒）。Black・isort・Flake8・差分検査に成功、実装ファイルのBanditは全重大度0件。追加した照合の両分岐と実行行をカバレッジで確認した。モジュール全体は81%であり、全体100%とはしない。ローカル証跡はGit管理外の `tmp/reward-target-coverage`。日本語の応答と実差分を自己レビューし、追加の指摘なし。

- 修正前の再現テストは、反映先が変わっても200となり失敗。
- 報酬APIテストで通常反映・同一対象への再反映・PLの更新/反映拒否を検証する。
- 参加者編集APIで別の6版または7版キャラクターへ変更した後、再反映が400となり、旧成長記録の経験点と反映日時が維持され、新キャラクターの記録が作られないことを確認する。
- 元のキャラクターに戻して再反映すると、既存の1件だけが更新されることも確認する。

DBスキーマ・Secrets・費用・外部サービス設定の変更はない。共有DB・実ユーザーデータの修正、実環境反映は未実施。既に誤更新された履歴の自動復元は行っていない。ロック順は従来の報酬・参加者・成長記録のままで、今回のテストはSQLite。PostgreSQLでの同時反映と候補CIの結果は別途確認する。

復旧は本変更のコミットをrevertできるが、誤った成長記録の更新も復帰する。データ保持を優先して修正を維持することを推奨する。
