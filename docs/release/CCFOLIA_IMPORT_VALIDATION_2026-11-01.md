# CCFOLIA取込の入力検証と取消保証

## 問題と修正

CCFOLIA JSON取込で、技能値の範囲外、名前・プロフィールの文字数超過、DBで表現できない整数や文字を渡すと、500応答になる場合があった。7版の文字数超過はSQLiteでは保存される場合もあった。

6版・7版とも、取込する詳細と技能のモデルフィールドを保存前に検証する。NUL文字とUTF-8で表現できない文字も拒否する。名前を使った既存版の検索は検証後に行う。入力の検証失敗は、入力値やDB例外を含まない日本語の400応答に変換し、既存のトランザクションで登録本体・詳細・先行して保存した技能を取り消す。通常のDB障害は入力不正の400へ変換しない。

技能値0〜999と既存のフィールド制約を使う。HP/SAN等へ新たな正数制限は加えない。保存可能なSAN負値、7版の幸運0、無料ユーザーによる取込、同名キャラクターの版履歴は維持する。新しい課金条件・権限・DB schema・マイグレーションはない。

## 検証

- 修正前の隔離SQLiteでは8試験中34サブケースが失敗した（500応答29、保存成功201応答5）。
- 文字検証の追加前には、実PostgreSQL 18/TLSでNUL・不正Unicodeの20サブケースが500応答になった。最初の修正後にも名前検索前の検証漏れ4件が残り、修正して再確認した。失敗記録は保持する。
- 最終ソースを、専用内部DockerネットワークのPostgreSQL 18に、証明書・接続先検証付きTLS、非superuserで接続して54試験成功・省略0。実ユーザーデータや共有DBは使わない。
- Windowsのメモリ内SQLiteではNodeによる出力・再取込5試験を含む59試験成功・省略0。製品コードの追加実行可能23行と追加4分岐は全て実行した。Windows試験環境は専用venvのTwisted 26.10と既存の他依存を参照し、全111依存の固定環境とは扱わない。元venvは変更しない。
- 正常な日本語・上限境界、6版/7版、無料利用、幸運0、同名の3世代、既存版の保全、先行技能を含む失敗時の全件取消、模擬DB障害の500維持を確認する。
- Black・isort・Flake8・Banditと差分・日本語エラー文を確認する。通常Dockerfileの配布物とCIの結果はPRに追記する。

テストの500応答には意図した入力不正の再現と模擬DB障害が含まれる。実AWSの障害復旧を検証した証拠にはしない。

## 公開条件と復旧

この修正だけで外部連携の受け入れ条件I07を完了にしない。[公式Clipboard API](https://docs.ccfolia.com/developer-api/clipboard-api)で扱うJSONと、実際の受取側での6版・7版・画像・ダイス・再出力の確認を区別する。実CCFOLIAルームへの書込みや通知は実施しない。

mainマージは別途承認対象。AWS反映・共有DB適用・実データ更新・Stripe操作・外部通知・正式公開は含まない。未配備のコードはrevert PRで戻せるが、入力による500や不正な文字数の保存も再発する。DB逆移行は不要。元25受け入れ定義、OS53指摘、正式公開No-Goを維持する。
