# 技能作成の入力エラーとトランザクション（2026-10-29）

PR #34の固定headde00c025を基点に、登録済みの技能作成APIを修正する。6版・7版とも、負数や職業/趣味ポイント超過、合計999超過がHTTP500になっていた。作成の途中で例外が起きると、既に保存した行が残る場合も再現した。

## 変更

`CharacterSkillViewSet.perform_create`から既存の所有者確認・版別保存処理を呼び、DBトランザクションで囲む。Djangoのモデル入力エラーだけを、更新APIと同じDRFの400応答へ変換する。項目別の辞書と項目なしのメッセージ一覧を保ち、既存の日本語エラーを使用する。トランザクション内の入力エラーや予期しない例外では保存を取り消す。

正常な201、他者の公開キャラクターへの404、予期しない障害の500を維持する。入力を受け入れる上限・計算式・所有権やURL構成は変更しない。新しいルートや利用者向け文言は追加しない。既存の更新失敗ログの情報保護と調査用ID保持も維持する。

## 検証

実URLのPOSTが`create` actionへ解決されることを確認し、使い捨てDB上の両版APIで再現した。最初の14入力ケースが500となり、既存の割り当てを含む予算超過・保存後の失敗も加えた最終の修正前検証では22 subcasesが失敗した。保存後の失敗では、作成行が残ることも確認した。

修正後の隔離PostgreSQL18.3・Python3.11.18/Django5.2.17で関連50件・66 subtests成功、省略なし。SQLiteでも関連39件・28 subtests成功。負数、職業/趣味の個別上限と既存割り当て合計、合計999、辞書/一覧形式のモデルエラー、入力エラー/予期しない障害の発生前後のDB状態、両版の正常保存と他者拒否を確認した。

PostgreSQL CIに新規10テストを追加する。通常配布物と最終headのCI結果はDraft PRの説明へ記録する。commit後の応答喪失・冪等性や、同時操作での予算競合を証明する試験ではない。

## 影響と復旧

DBスキーマ・共有DB/実データ・Secrets/権限・AWS資源・依存関係・費用・外部通知に変更はない。コードのコミット・通常push・Draft PR作成までを行い、mainマージとAWS反映は別途承認対象とする。先行PR #33/#34のheadや承認範囲を変更しない。

復旧はこの差分のrevert PR。ただし入力エラーの500と途中保存が再発する。原則として修正を保持した追加対応を優先する。OS50指摘・Twisted RC2、実サービス・性能/復旧等の[正式公開条件](FORMAL_RELEASE_ACCEPTANCE_MATRIX.md)とNo-Goを維持する。
