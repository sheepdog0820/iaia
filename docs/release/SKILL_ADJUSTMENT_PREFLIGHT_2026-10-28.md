## 事前検査

既存のPostgreSQL `REPEATABLE READ READ ONLY`トランザクション内で、0068の適用記録と6版/7版ごとの行数・旧ボーナス非ゼロ件数・bonus/other各合計・合算後に32ビット整数の範囲を超える件数を返す。加算前にbigintへ変換し、検査自体の桁あふれを避ける。既存の移行履歴・制約検査を保持し、JSONの`format_version`を2へ上げる。

実行例は`python manage.py release_database_preflight`。読み取り専用であることをDBが強制する。探索者名・技能名・行ID・接続情報は出力せず、SQL失敗時は部分結果も出力しない。既存のstatement_timeout 5秒・lock_timeout 1秒を維持する。対象テーブルがない旧スキーマも正常扱いにしない。

修正前は新規4テストが失敗し、既存9件が成功した。修正後は隔離PostgreSQL 18.3で、事前検査・履歴モデルの0067→0068→逆移行→再適用・復元検査ランチャーの計22テスト・25 subtests成功、省略なし。正負の旧内訳・上限/下限超過・空テーブル・適用記録なし・欠落テーブルを検証し、前後の全行不変と非公開名の非出力を確認した。コマンド全38実行文/8分岐、変更7実行文をすべて実行した。

最初にSQLiteを選択した試行は13件すべて省略となったため検証成功には算入せず、明示的に隔離PostgreSQLを選択して上記の再現・成功を確認した。Black/isort/Flake8/Bandit・文字コード・日本語エラー・自己レビューの結果はDraft PRに記録する。

この集計は移行の実行許可、全行の保存・比較、復元成功を証明しない。0068適用記録があっても旧ボーナスが残る場合やoverflowが1件以上ある場合は、そのまま適用・完了扱いにしない。

1. PR #28等の採用範囲を承認後のmain SHAへ固定し、そのSHAの通常配布物・稼働版との差分・OS監査を照合する。OS50指摘とTwisted RC2を未解決のまま正式公開可としない。

4. 共有0068適用と既存Webサービスのイメージ更新・必要なstatic収集をそれぞれ具体的に承認してもらう。候補SHA・現行定義55とdigest・検証・未確認事項・戻し方を更新して提示する。
