# 履歴経由の非公開関連情報の保護

## 再現した問題

PlayHistoryの関連IDには閲覧権限チェックがなく、他人の非公開シナリオ/セッションを指定したPOSTが201、PATCHが200になった。応答に非公開題名などが含まれ、既存履歴も現在の閲覧権限を確認せず関連情報を返していた。隔離テストDBで再現し、修正前6ケース中4ケース（subtest等を含む失敗6件）が期待条件を満たさなかった。

## 修正

- シナリオ指定は既存のシナリオメモと同じ閲覧規則（公開、またはcan_view_scenario）を適用。
- セッション指定は本人が作成者/GM、または既存の基本閲覧権限を満たす場合のみ許可。未指定/nullは維持。
- 作成/更新時の拒否は400と日本語の一般的な案内で、非公開題名を返さない。
- 既存履歴でも読み出し時に再確認し、閲覧不可のシナリオは「閲覧できないシナリオ」と空の作者/システム名のみ返す。閲覧不可のセッションはIDをnullにして題名を返さない。
- 本人の履歴・メモ自体は削除しない。関連情報が非公開化された後も自分のメモを更新できる。
