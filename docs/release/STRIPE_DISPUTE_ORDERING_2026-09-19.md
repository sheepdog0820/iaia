# 異議申し立て通知の順序変動への対応

## 問題と変更

勝訴通知を処理した後に古い `charge.dispute.created` が届くと、解決済みの異議申し立てによってプレミアムが再停止する問題を回帰テストで再現した。Webhookでは通知内の古い状態をそのまま使わず、対象利用者の購読レコードをロックしてStripeの現在のDisputeを照会する。Charge・顧客・Disputeの対応を照合し、現在の状態に基づいて既存の停止・復旧処理を呼ぶ。

Stripe照会の一時失敗、参照の不一致、未知の状態は500として再送可能にし、権限変更をロールバックする。展開された参照オブジェクトにも対応し、監査にはIDのみを保存する。対応するアプリ顧客が存在しないイベントは無視する。元のイベント種別はWebhook記録に残り、権限監査の状態は照会時点のものとなる。

## 検証

- 初期の3回帰テストで修正前の失敗を確認。関連277テスト成功（24.748秒）。
- 使い捨てPostgreSQL 18.3で16テスト成功（4.030秒）。開始・終了通知を別DB接続から同時処理し、最新状態を使って権限が有効となり、復旧監査が1件に留まることを確認した。
- 実Stripeサンドボックスで開始通知を署名付きのまま一時保持し、勝訴通知を先に処理してから開始通知を届け直した。権限は有効のまま、監査状態はwon、両イベントはsucceededとなった。試験本体の10項目成功。[イベント証跡](STRIPE_DISPUTE_ORDER_EVENTS_2026-09-19.json)を参照。
- 実試験終了時にテスト購読の解約成功を確認した。後片付けで発生したsubscription.deletedは証跡取得時点でprocessingであり、この終了通知のアプリ処理完了までは本試験の成功範囲に含めない。
- Black/isort、flake8、Bandit、差分検査を通過。新しい利用者向け文言はなく、英語の例外文言は内部診断用。ソースレビューで今回の修正範囲に追加の修正必須事項は認めなかった。

テストは認可済みのサンドボックス、専用顧客、公式テストPaymentMethod、使い捨てローカルDBを使用し、実課金・実メール送信は行っていない。受信器・Stripe CLI転送・専用PostgreSQLコンテナを停止し、一時DBを破棄した。

## 制限と反映

同一Disputeの逆順は対応したが、未受信イベント、返金との全組合せ、メール配送保証、Checkoutと解約の競合を網羅したものではない。warning_closedの停止、preventedで過去の停止を自動復旧しない既存方針は変更していない。追加の公開条件とAWS実接続の確認が残り、正式公開はNo-Go。

本変更の追加マイグレーションはない。同じ作業ブランチの0065・0066は共有DBに未適用。main/AWS、Secrets、料金、税設定、継続費用は変更していない。切戻しは本修正のrevertで可能だが、逆順通知による誤停止が再発するため、課金機能の停止と併せて判断する。最新コミットのCIはpush後に別途確認する。
