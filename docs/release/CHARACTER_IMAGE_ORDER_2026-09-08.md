# 画像追加時の表示順序修正

確認日: 2026-09-08。

## 問題と修正

画像の自動順序は既存の最大値に1を足す仕様だが、`max_order or -1` が0も未登録と同じ扱いにしていた。このため先頭画像の順序が0のとき、次にアップロードした画像も0となる。6版・7版ともAPIで2枚目の順序が期待する1ではなく0となることを再現した。

未登録を表すNoneだけを-1として扱い、最大順序0の次は1にする。順序を明示指定した場合は指定値を保持し、その後の自動追加は既存最大値の次にする。既存の画像順序やファイルを一括変更する処理は追加していない。

## 検証と影響

新しいAPIテストは6版・7版それぞれ、5回の追加で順序が0、1、2、7（明示指定）、8となること、保存した順序とメイン画像1件を確認する。修正前は両版で2枚目の0と1の不一致により失敗した。

修正後は同時追加・複数画像・画像APIの関連3モジュール、計45件がPostgreSQLで成功。Black・isort・flake8、差分・日本語表示保持のレビューも成功し、追加の指摘はない。試験コンテナとネットワークは削除済み。最新コミットのCI完了と実配備は未確認。

隔離PostgreSQL 18.3と一時MEDIA_ROOTで検証。元の本番イメージbca01195へ対象ソースと既存の同時追加修正を読み取り専用でマウントした局所検証であり、新しい配布イメージや共有環境での確認ではない。実行証跡は `tmp/image-order-probe/red.log` と `captured.log`。

DBマイグレーション・実データ変更・権限変更・費用増加はない。過去に重複した順序の自動整理は含まない。修正をrevertすると追加時の順序重複が再発するため、正式公開候補から除く場合は影響の再評価が必要。
