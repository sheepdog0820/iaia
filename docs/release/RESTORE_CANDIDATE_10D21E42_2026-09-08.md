# 固定候補10d21e42の隔離復旧訓練

2026-09-08、アプリ候補10d21e42の通常実行用イメージで、PostgreSQLと画像のバックアップ・復元を検証した。これは現候補でのローカル復旧証拠であり、実RDS/S3の復元や正式公開合格ではない。

## 条件

- イメージ `tableno-formal-release:10d21e42`、ID `sha256:dec00ade1cc08142732ee124b9082d2c19e88003cac4a40339d3efc302e69cf2`。HEAD cd9bf29cと10d21e42の差分はdocs以外なしと確認。
- PostgreSQL 16.15、外部接続不可の専用internal network、公開ポートなし。データ領域は使い捨てtmpfs。
- APP_ENV=local、試験用設定でファイルストレージ、locmemメール・キャッシュを利用。実Secrets、外部サービス、worker/beatは使わない。
- アプリソースの上書きはせず、試験スクリプト・設定・合成データだけを `/drill` にマウントした。
- 非rootのアプリから空の試験DBへmigrateし、GM/PL、非公開セッション、秘匿HO、13×17 PNGを作成した。実ユーザーデータは使用しない。

再現用のGit管理外ファイルは `tmp/restore-drill-10d21e42/run.py`、`probe.py`、`drill_settings.py`。ログ・dump・合成画像・expected.json・results.jsonは同ディレクトリに保存。旧訓練ファイルは上書きしていない。

補足として、固定イメージ内の非rootユーザーが合成tarの06755ファイルを通常展開した場合と、--no-same-owner/--no-same-permissionsを指定した場合を隔離tmpfsで比較した。どちらも所有者10001・0755になった。通常手順に今回再現できた特殊権限の復元不具合はなく、実データやrootでの展開へ一般化しない。

## 残る条件

この訓練ではDB内容・採番・画像・所有関係を照合したが、全スキーマ/ACLの独立比較、HTTPでの全権限検証、同時書き込み、実規模負荷は含まない。実RDS/S3の特定世代復元、DBと画像の時点整合、実サービス復旧、合意RPO/RTOは引き続き必要。旧イメージへの切り戻し訓練も本記録では更新していない。

共有環境のDB・Secrets・アクセス権・費用は変更していない。文書の差分・リンク・UTF-8/LFを確認する。本訓練の結果をアプリ全体のテスト合格へ読み替えない。
