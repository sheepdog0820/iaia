# 画面スクリプト検証用データの分離

## 確認した問題

[CI実行34020546050](https://github.com/sheepdog0820/iaia/actions/runs/34020546050)のWebKitで、画面スクリプト検証が別のテストのセッションを選び、合成YouTube動画IDのサムネイル404を検出した。従来は一覧APIの先頭IDを選び、取得できない場合は詳細画面の検証を省略していた。テストの順序と残存データによって検証対象が変わる。

## 変更

`tests/e2e/flows/ui-scripts.spec.ts` の主要画面検証で、専用のグループ・シナリオ・セッションを実APIから作成し、そのIDで詳細画面を確認する。作成失敗や不正なIDは失敗にし、詳細画面の省略は廃止する。コンソールエラーの許可範囲は広げない。アプリの表示・権限・保存処理は変更しない。

作成データは従来同様に隔離テストDB内の `E2E` 名の合成データ。共有環境や実ユーザーデータには適用していない。自己レビューではセッションの公開範囲を既存の `group` 選択肢に合わせた。

## 検証方法と未解決事項

現在のテストファイルをPlaywright 1.63の隔離コンテナーに重ね、コミット済みの開発ログインヘルパーを使用する。別途検証中の未コミットヘルパー変更は含めない。合成動画 `yt_reorder_003` とサムネイルURLを持つ既存セッションを空のSQLiteに用意し、3ブラウザで `ui-scripts.spec.ts` を実行する。実サービスの認証情報・ユーザーデータは使用しない。

検証スクリプトは `tmp/run-ui-health-isolation.ps1`、データ作成は `tmp/ui-health-contamination-seed.py`、結果は `tmp/ui-health-isolation-targeted.log` と `tmp/ui-health-isolation-targeted-output/results.json`。

対象検証は3ブラウザ合計6件成功（42.6秒、終了コード0、再試行なし）。専用レコードの作成と各詳細画面の確認まで成功した。差分の空白チェックにも合格した。画面文言の製品変更はなく、追加した日本語は合成テストデータ内のみ。TSのLFは維持しているが、既存の `.gitattributes` にTS専用のLF指定がないため、Gitがチェックアウト時のCRLF変換警告を出す点は残る。

先行する準備実行では `youtube-links.spec.ts` を3ブラウザで実行し、Chromium・Firefox成功、WebKit失敗で停止した。ドラッグ後の動画ID順序が期待 `[8,9,7]` に対して `[8,7,9]` だった。この実行では画面スクリプト検証は開始されていない。ログとトレースは `tmp/ui-health-isolation.log`、`tmp/ui-health-isolation-output/` に保持する。後続の対象検証に成功しても、YouTube並べ替えの失敗が解消したとは扱わない。

初回の全体検証のGoogle保存クリック失敗と、後続の共通CSSの修正・検証は [別記録](DEV_LOGIN_READINESS_2026-09-06.md) を参照。後続の全体実行では本ファイルの6件はすべて成功したが、全体ではセッション作成1件が失敗し、別途対象テストを修正した。今回の対象テストだけで全体のマージ可否を判断しない。復旧はこのテスト変更の取り消しで可能であり、DBスキーマや実データの復旧は不要。
