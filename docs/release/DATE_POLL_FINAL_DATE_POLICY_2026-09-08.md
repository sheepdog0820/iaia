# 確定後の日程変更をセッション編集に限定

ユーザーがA案「確定後はセッション編集で変更する」を承認した。別の投票による確定日上書き、確定済み投票の再開、確定日の直接編集を拒否する。セッション編集では現在の開催日時を変更でき、投票での確定日は履歴として保持する。

確定時に対象セッションをロックし、現在の開催日時または確定履歴がある場合は日本語エラーで拒否する。異なる投票から同時に確定した場合も成功は1件のみ。失敗した投票の確定日・締切状態は変更しない。投票画面では「この投票での確定日」と「現在の開催日時」を分けて表示し、変更の入口を案内する。

修正前は関連する3テスト中、上書き・再開・履歴編集の期待に4失敗。修正後は隔離PostgreSQL16で関連32テスト成功（並行処理を含み省略なし）、追加したシリアライザ検証5行・4分岐をすべて実行。Black/isort/Flake8、差分・文字コード・日本語文言を確認。Chromium/Firefox/WebKitの既存日程投票フローに表示確認を追加し、3件成功、再試行なし。

証跡: `tmp/final-date-red.log`、`tmp/final-date-pg-green.log`、`tmp/final-date-coverage.json`、`tmp/final-date-browser.log`。PostgreSQL CIにも新しい回帰テストを追加した。実AWSへのアプリ反映と最新候補CIの完了は別途必要。DBマイグレーション、既存データ変更、課金・権限変更は含まない。
