# CCFOLIA形式JSONの版情報保持（2026-10-28）

統合候補PR #20の714c2ed0を基点に、既知759aca7aから必要な差分だけを分離する。タブレノの7版探索者をCCFOLIA形式へ出力し、そのJSONを版指定なしで再取り込みすると6版として保存される問題を修正する。サーバー出力と実ブラウザーのコピーにトップレベル`edition`を含める、製品2行の変更である。

6版は`6th`、7版は`7th`を出力する。版情報を持たない従来JSONの6版既定値と、取り込み画面での明示的な版選択を維持する。能力値のスケール、判定コマンド、技能・HP/MP/SAN・幸運の既存方針、無料の取り込みは変えない。6版・7版以外のシステムは追加しない。

## 検証

- 取り込みの実行を版情報フィールドのassertより先に行い、旧コードが実際に7版を6版として保存することを確認した。新規4テストのredは6失敗・3成功（subtestの失敗を含む）。
- 修正後はSQLite4テスト・5 subtests成功。サーバー出力、実JavaScriptをNodeで生成したコピーJSON、従来の版情報なしJSON、7版の幸運0を、手動の版指定なしで再取り込みして確認した。
- 実際の作成・出力/コピーボタン・貼り付け・版選択・取り込み後の保存値と見出しを、Chromium/Firefox/WebKitの4経路ずつ計12ケースで確認した。12成功・省略0・不安定判定0・予期しない失敗0。各ケースでpageerrorがないこともassertした。OSのクリップボード権限は模擬し、JSONデータを捕捉している。
- UIは専用Dockerのtmpfs上のSQLiteとlocmemメールで実行した。127.0.0.1への要求・実効ポート割り当てを確認し、終了後に所有ラベルを確認してサーバーとDBを削除した。通常のローカル/共有DBや既存サーバーを使っていない。初回はポート割り当て完了待ちの調整で起動検査を停止し、検査条件を維持した再実行が成功した。
- 関連5モジュールの隔離PostgreSQLは65テスト・15 subtests成功、省略なし。Black/isort、Flake8、Bandit、JavaScript構文、差分の空白検査が成功した。自己レビューで追加の対処事項はなく、変更は版情報のメタデータで表示文言の追加はない。
- カバレッジは複数行の辞書を代入行として記録するため、追加キーの行を独立した実行行としては数えない。包含する辞書代入の実行・欠落行なしと、新しい値を検証するAPIの往復assertを確認した。モデル全体100%の主張はしない。最初の計測検査はキー行の直接記録を期待して失敗し、製品・テストを変えずに計測結果の解釈を修正した。
- 通常配布物と最終CIは未完了。

## 未確認と承認境界

`edition`はタブレノの再取り込み用メタデータで、[公式Clipboard API](https://docs.ccfolia.com/developer-api/clipboard-api)の定義済みフィールドではない。CCFOLIAが追加情報を保持することや、実サービスから再コピーしたJSONで自動判定できることを保証しない。情報が失われた場合は取り込み画面で7版を選ぶ。今回の成功はタブレノの未変更JSONの再取り込みであり、実CCFOLIAとの往復・画像/表情差分登録の完了証拠にしない。

実CCFOLIA・AWS・実ユーザーデータ・Secrets/権限・外部通知は変更しない。モデル/マイグレーション、料金・常設資源・継続費用の変更もない。main追加マージは別途対象headと検証結果を示して承認を確認する。復旧はrevert PRで、7版の再取り込み時に明示的な版指定が必要な旧状態へ戻る。正式公開No-Go、OS指摘・Twisted RC2、有料必須ゲート、外部連携・性能/復旧等の受け入れ条件は維持する。
