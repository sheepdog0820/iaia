# 通常配布イメージでの画像解像度検証

確認日: 2026-09-08。対象アプリコミット: `1edab4f2`。

## 配布物と環境

クリーンなGitアーカイブから通常のDockerfileで `tableno-formal-release:1edab4f2` をビルドした。イメージIDは `sha256:f0cc1aed8c16e4080e77d28610053fd104216bbfe68930c9b8e17cd9cb17b127`。accounts/scenarios/schedules/tableno/support/templates/static配下553ファイルのSHA-256が元ソースと一致した。アプリソースの差し替えマウントはない。

ローカルの内部ネットワークに、アプリ0.25 CPU/512 MiB、PostgreSQL 18.3（2 CPU/1 GiB）、Redis 7（128 MiB）を配置。空のDBへ通常entrypointでマイグレーション・静的収集を実行し、Daphneを起動した。試験用ユーザーと非公開の6版・7版キャラクターを各1件作成した。実データは使用していない。

本番設定を使用したが、内部HTTPのためHTTPSリダイレクトは無効化し、試験クライアント内でCookieのSecure属性を解除した。構成済みRedisへ作った合成セッションを使用し、実ログイン・TLS・OAuthを試験した結果にはしない。

## 実HTTP結果

画像はパディングを足さずPillowで生成した。各ケースを6版・7版へ1件ずつ順番に送信し、すべて期待した応答となった。送信ファイルはいずれも5 MiB未満で、単なる送信サイズ超過による拒否ではない。

関連ログは `tmp/image-resolution-1edab4f2/http-results.log`、`source-match.json`、`server.log`。試験用コンテナとネットワークは所有ラベルを照合して削除済み。イメージとローカル証跡は保持する。セッション値はGitへ含めない。
