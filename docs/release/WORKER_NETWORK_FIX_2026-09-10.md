# バックグラウンドサービスの通信経路修正

## 発見した問題

開発AWSはNAT Gatewayがなく、Webは公開サブネット・公開IPで外向きに通信している。一方、Terraformのworker/beatサービスは非公開サブネット・公開IPなしに固定されていた。現行の開発環境でこの定義を使うと、イメージ取得やGoogle等への通信に必要な経路を確保できない。

2026-09-10の読み取り確認ではNAT Gateway一覧は空で、非公開サブネットのルートには以前のNATへの参照が残っていた。既存ルートの変更やNATの復元は行っていない。

## 修正と検証

worker/beatとも、既存のWeb・背景透過タスクと同じ選択規則に変更した。NATありでは非公開サブネット・公開IPなし、NATなしでは公開サブネット・公開IPありとする。セキュリティグループは既存ECS用を維持し、インターネットからの着信許可を追加しない。

Terraformのmock providerでAWSの作成・変更なしにplanを評価するテストを追加した。修正前はNATなしで公開IP・サブネット選択の2条件が失敗し、NATありは成功。修正後は2構成・4条件すべて成功した。Terraform 1.15.6でfmt・validateも成功し、同じ検査をCIに追加した。テストファイルはplan時のモック値を使うためTerraform 1.9以降を必要とする。

モック検査は実通信やAWS起動の証明ではない。実AWSへの適用は未実施で、サービス数、権限、既存DB、継続費用に変更はない。将来この設定でサービスを起動すると公開IPv4料金が発生するため、起動承認時の費用に含める。

## 起動前の残作業

ブローカー設定をWebのキャッシュ・セッション保存方式から分離する構成を用意する。既存ログインを切り替えないこと、worker起動時に動くジョブの範囲、夜間停止運用との整合、Redisの保護、費用、停止・復旧手順を確定して承認を求める。beatはハンドアウト公開・期限切れ処理も行うため、worker起動と分けて影響確認する。

現在のGoogle連携と概算費用は[再連携確認記録](GOOGLE_RECONNECT_2026-09-10.md)を参照。今回の修正だけでGoogle実同期が可能になったとは扱わない。

復旧は作業ブランチ上のこの設定差分を戻す。AWSへは適用していないため、現在の稼働環境に復旧操作は不要。
