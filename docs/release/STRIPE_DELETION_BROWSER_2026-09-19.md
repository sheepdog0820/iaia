# 退会画面のブラウザー検証

実装743e1e46に対してPlaywright 1.63.0の退会回帰テストを追加した。Chromium・Firefox・WebKitで各2テスト、計6テストが成功（約1分）。

## 確認内容

- 新規登録した無料利用者が退会画面を開き、日本語の警告を確認する。
- 確認モーダルのキャンセルでは退会POSTが送られず、再読み込み後も操作を継続できる。
- 誤ったパスワードで確定しても退会せず、日本語のエラーを表示する。
- 正しいパスワードで確定すると退会・ログアウトする。ダッシュボードへの再アクセスはログインへ移動し、元の認証情報で再ログインできない。
- 支払遅延、権限停止、期間末解約待ちの3状態では、契約未終了の警告と課金管理への導線を表示する。削除を確定しても課金管理へ移動し、ログインとダッシュボードへのアクセスを保持する。

## 環境と限界

専用SQLite DBと127.0.0.1:8915で実行し、環境ファイルを読み込まず、メールはメモリー内バックエンドを使用した。契約状態はテスト自身が登録した利用者の専用データで再現し、Stripe APIへの実接続は行っていない。準備処理はDEBUG・APP_ENV=local・ENV_FILE空を必須とし、専用名・example.testのメールアドレス・非管理者条件が一致した利用者だけを操作する。

通常の退会によるデータ削除と、保護ケースのfixture削除後に利用者0件を照合した。一時DBを破棄し、専用ポートの待受終了を確認した。普段のローカルDB・共有AWS・mainは変更していない。

最初の実行では、退会後に匿名ホームからログインへ遷移する仕様をテストが考慮しておらず、ホームURLを待って失敗した。テストの待機先を実際のログイン画面に修正し、最終実行は6件すべて成功。アプリ実装の変更はない。faviconの404とページ遷移時の開発サーバーのBroken pipeログがあり、画面の全リソースが無エラーだったとは扱わない。

署名付き通知との同時処理、実Stripe契約を伴うブラウザー退会、AWSでの全フローは引き続き未確認。[API・PostgreSQL検証](STRIPE_DELETION_CHECKOUT_2026-09-19.md)と検証範囲を区別する。743e1e46のCIは記録時点で4ジョブ成功・2ジョブ実行中であり、全体合格とは扱わない。
