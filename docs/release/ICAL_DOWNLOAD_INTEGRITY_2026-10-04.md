# ICSダウンロードの文字・時刻保持（2026-10-04）

## 対象と結論

`GET /api/schedules/calendar/export/ical/` に、入力中の改行による予定/プロパティ混入、TEXT値の区切り文字の未エスケープ、日本語長文の未折り返し、UTC時刻をfloating timeとして出力する不備を確認した。専用ブランチ `codex/ics-export-integrity-20261004` で修正・ローカル検証した。main・AWSには未反映で、正式公開はNo-Goを維持する。

購読用ICSは既に文字処理を持っていたが、ダウンロード用は別実装だった。両方が同じ `schedules/ical_text.py` の処理を使うようにした。購読側の互換用関数名は維持し、抽出範囲・閲覧権限・予定ステータス・アラームの条件は変更しない。ダウンロード側の予定開始/終了をUTCへ変換して `Z` を付ける。ユーザー入力を削除せず、受信側で改行や文字を復元できるTEXT表現にする。

[RFC 5545](https://www.rfc-editor.org/rfc/rfc5545) の3.1（CRLFと75 octetsの折り返し）、3.3.11（TEXTの改行・コンマ・セミコロン・バックスラッシュ）、3.3.5（UTCとfloating timeの区別）を基準にした。タイトル、説明、場所、カレンダー名、GM/グループ名、表示アラームの説明を対象とする。コロンはTEXT内でエスケープしない。

## 再現・検証

- 修正前の6テストは3テスト成功、3テスト失敗。5入力欄×CRLF/CR/LFの15サブテストすべて失敗し、タイトル中のCRLFでは `BEGIN:VEVENT` が本来の1個から4個に増えた。区切り文字の保持と末尾CRLFも失敗した。
- 続くUTCの回帰テストも修正前に失敗。UTC数値に `Z` がなく、受信側のタイムゾーンに束縛されないfloating timeになっていた。
- 最終結果はWindowsの隔離SQLiteメモリDBで31件成功（17.315秒、終了0）。リポジトリの29件に独立パーサーの2件を加えたもの。ダウンロード・購読の既存回帰、5入力欄×3改行、75 octets境界、日本語/絵文字、空の予定一覧、アラームなし、他人の非公開予定の除外、未認証拒否を確認した。
- 共通文字処理17文/4分岐、新規回帰テスト136文/10分岐は行・分岐100%。既存viewsの変更された実行可能15文もすべて実行済み。views全体の100%を意味しない。
- 独立パーサー `icalendar==7.3.0` を一時ディレクトリだけに導入し、APIClient応答から予定1件・日本語TEXT・実改行とリテラル `\n` の区別・場所・UTC開始/終了・2アラームと相対時間を復元。キャンセル・任意項目なしも成功し、各componentのparser errorsは0。アプリの依存/ロックは変更していない。
- 同パーサーは非標準拡張 `X-WR-CALNAME` をUNKNOWNとして扱うため、この項目はwire値の保持だけを確認した。実カレンダーアプリの名前表示を証明する結果ではない。
- 固定イメージ `sha256:9c829979f8a69e075b61f7769c3b26d7a4fa003316c47d07e1982f7d7b94f4ad` に変更ソース・テスト・一時パーサーを読み取りマウントしたLinuxコンテナでも同じ31件が成功（12.749秒、終了0）。`--network none --memory 512m --rm`、SQLiteメモリDB、実資格情報/外部通信なし。新しい全ソースの配布イメージ構築やAWS配送を代用しない。コンテナは終了・削除済み。
