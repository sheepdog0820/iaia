# DBとメディアを一緒に復旧する際の受け入れ条件

2026-09-08、候補af2bceedのモデル定義と既存の復元手順を照合した。これは検査設計であり、実RDS/S3復元の成功記録ではない。RPO/RTOの基準はユーザー回答待ち。

## 既存の試験で確認できる範囲

[最新候補の追加試験](RESTORE_MEDIA_7FC6B61E_2026-09-08.md)では、登録済み具体モデルの11ファイル項目をすべて合成データで埋め、PG18.3の別DBへ復元して91テーブル・621行・87シーケンスと11ファイル/参照の一致を確認した。以下の画像1件の試験を補強するが、実S3世代選択・時点整合・実HTTP権限は未確認。

[ローカルの復元試験](RESTORE_CANDIDATE_10D21E42_2026-09-08.md)は、合成DB・画像1件・所有関係・内容ハッシュを照合している。実データ規模や全ファイル種別、同時更新中の時点整合は対象外。

[承認待ちのRDS復元案](RDS_RESTORE_APPROVAL_2026-09-08.md)は固定snapshotを別DBへ戻し、最小プローブで移行履歴・スキーマ等を読み取る案。S3を復元したり、アプリのメディア参照を網羅したりする承認・検証ではない。本書を追加してもその実行範囲を拡張しない。

## メディア参照の検査対象

| 用途 | ソース上の定義 |
| --- | --- |
| プロフィール | CustomUser.profile_image |
| キャラクターの代表画像 | CharacterSheetSystemData.character_imageを継承する具体モデル |
| キャラクターの複数画像 | CharacterImageSystemData.imageを継承する具体モデル |
| シナリオ画像 | ScenarioImage.image |
| セッション画像 | SessionImage.image |
| ハンドアウト添付 | HandoutAttachment.file |
| 問い合わせ添付 | SupportMessage.attachment |
| 背景透過の入力・結果 | BackgroundRemovalJob.source_image / result_image |

一覧はaccounts/schedules/scenarios/supportのモデル定義から抽出した調査起点である。abstractの_LegacyCharacterImageもソースにあるため、ソース名だけで稼働テーブルと判断しない。実検証前に候補のDjangoモデル登録と復元DBのスキーマを照合し、継承先・実ストレージ・空欄可否を確定する。URL文字列などFileField以外の外部参照も別途調べる。

## 照合の手順と判定

1. 復旧対象時刻、DBのsnapshotまたはPITR時刻、メディアの回復可能範囲、利用候補SHAを固定する。DBだけ過去へ戻して現在の画像をそのまま使う前提を置かない。
2. 読み取り用の復元DBから、モデル・行の識別子・フィールド・ストレージキーの非空参照を収集する。識別子やキーは個人情報を含む可能性があるため、公開ログやPRには出さず、アクセスを限定した証跡に保管する。
3. 各参照に対応するオブジェクト世代を選ぶ。VersionId、更新時刻、delete marker、長さ、利用可能なチェックサムと照合する。DBのトランザクションとS3の更新は同一ではないため、時刻が近いだけで内容一致としない。必要な世代を特定できない場合は未解決として残す。
4. 承認された隔離先で内容の取得・ハッシュ照合・画像のデコード、添付の保存形式を確認する。ETagを無条件に内容のMD5と解釈しない。欠落、内容不一致、復元時点より新しい内容、削除済み内容の復活を分類する。
5. 非公開のハンドアウト・問い合わせ添付・ユーザー画像を、元の所有者と閲覧権限のまま扱えることを確認する。別ユーザー・匿名・失効ユーザーによる取得も検査する。ファイルが存在するだけでは合格としない。
6. 背景透過などの処理中ジョブは、旧キューを無条件に再開しない。二重処理、古い入力の再送、削除済みデータの復活を防ぐ復旧方針と整合させる。保持期限・削除方針の判断も必要。
7. 対象参照総数、成功数、欠落・不一致・権限違反・未判定数と、開始から利用再開確認までの時間を記録する。対象の一部だけを調べた場合は分母と抽出条件を明示する。例外が未判断のまま、復旧完了やRPO/RTO達成と判定しない。

2026-09-08の読み取り確認では、aws-pre RDSは自動バックアップ7日、暗号化有効、S3 assetsはバージョニング有効。非現行世代の削除規則にNoncurrentDays=30・NewerNoncurrentVersions=3、削除マーカー整理も設定されていた。これらの設定は、必要な全世代の存在や復元成功を証明しない。

実オブジェクトの取得・複製・復元、権限変更、環境作成は実施していない。実行前に対象・操作・費用・後片付けを具体化し、その範囲の承認を照合する。実データをローカルへ無断で複製しない。文書追加は実DB・S3・Secrets・費用に影響せず、文書だけの訂正で取り消せる。
