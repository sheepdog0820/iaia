# 技能APIの同時保存と古い更新要求（2026-10-29）

PR #35の固定head b5ca4b06を基点に、技能の作成・個別更新を、一括更新と同じキャラクター単位で直列化する。ポイント上限・計算式・DBスキーマ・利用者向け文言は変更しない。

## 再現した不具合

隔離PostgreSQLで2つのリクエストを重ねると、6版・7版の職業/趣味ポイントで、各要求が残り全量を使い切っても双方が成功し、合計が上限の2倍になった。作成・個別更新だけでなく、一括更新との組み合わせでも再現した。一括同士は既存の親ロックで防げていた。

技能名だけを変更する古いPATCHが、先に保存されたその他ポイントを元に戻す問題も両版で再現した。保存後に例外が起きる場合は変更が残り、読み込み後に削除された技能は古いPATCHから再作成された。所有者が読み込み後に変わる状況でも再確認がなく、元の要求から更新できた。

最初の作成/個別更新の8ケースで上限超過を確認した。拡張した36組の競合と2組の部分更新では34 subcases失敗・4 subtests成功。別の保存後エラー・削除・所有者変更の8 subcasesも修正前に失敗した。すべて架空データ・使い捨てDBによる再現で、実ユーザーデータは操作していない。

## 変更と検証範囲

作成は既存のトランザクション内で、所有者を条件に親キャラクターをロックしてから保存する。個別更新も同じ親ロックを取得し、版別の技能を所属条件付きで読み直してロックする。その後にPATCHの指定項目を適用し、保存と副作用を同じトランザクションに含める。読み込み後の削除や所有者不一致は404とし、既存の400/500の区別と調査用IDだけの安全なログを維持する。

回帰テストは両版・職業/趣味の2種類・作成/個別更新/一括更新の9通りで36組を確認する。さらに、異なる項目への部分更新2組、保存後の入力/予期しないエラー4組、読み込み後の削除2組と所有者変更2組を確認する。所有者変更は権限の再確認を試す合成操作であり、所有権移譲機能を追加するものではない。

PostgreSQL CIの対象へ新規5テストを追加する。行ロックを使う2テストはSQLiteで代用せず、残る3テストと既存の技能API回帰をSQLiteでも検証する。確定したソーステスト・通常配布物・最終headのCI結果はDraft PRへ記録する。

修正後の隔離PostgreSQL18.3/Python3.11.18/Django5.2.17では関連55件・112 subtests成功、省略なし。SQLiteでも行ロック以外の関連42件・36 subtests成功、省略なし。Black/isort/Flake8・製品コードのBanditと差分整合性も確認した。通常配布物と最終CIはこのソース検証と区別する。

直接のORM/QuerySet操作、親の能力値を変更する別API、保存確定後の応答喪失や再送の冪等性全体を証明する試験ではない。同一キャラクターの3つの技能書き込みAPI間の整合性と、個別更新のトランザクションを対象とする。

## 影響と復旧

共有DB/実データ・AWS・Secrets/IAM・依存関係・費用・外部通知への変更はない。行ロックは対象キャラクターに限定し、先行PR #33〜#35のコードと承認対象を変更しない。mainマージ、AWS反映、共有DB0068適用、本番公開は別途承認対象とする。

復旧はこの差分のrevert PR。ただし上限超過・古い更新による変更喪失・途中保存などが再発するため、原則として修正を保持した追加対応を優先する。OS50指摘・Twisted RC2、および[正式公開の受け入れ条件](FORMAL_RELEASE_ACCEPTANCE_MATRIX.md)とNo-Goは維持する。
