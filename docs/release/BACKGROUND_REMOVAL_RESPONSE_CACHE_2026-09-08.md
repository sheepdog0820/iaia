# 透過結果APIのキャッシュ制御

2026-09-08。背景透過の結果取得APIは所有者を照合していたが、応答にCache-Controlがなかった。テストで完了画像の応答にno-storeがないことを再現し、ステータスAPIのdispatch全体へDjangoのnever_cacheとVary: Cookie, Authorizationを追加した。

完了画像の200、処理中の202、失敗時の503、他人のジョブへの404、未認証の401に、private/no-storeと両認証ヘッダーのVaryが付くことを検査する。画像内容・ダウンロード名とその改行対策・所有者限定取得は維持する。認証エラーも対象にするため、成功応答だけにヘッダーを付ける実装にはしていない。

この変更は、HTTPキャッシュへ保存させないための応答指示であり、過去に保存されたキャッシュの削除や実ブラウザ・プロキシの挙動を検証したものではない。実環境反映後のヘッダーと中継設定の確認、[CDN直アクセスの拒否](BACKGROUND_REMOVAL_CDN_PROTECTION_2026-09-08.md)は別途必要。

背景透過ジョブ・非公開作業ファイルの静的配信拒否・問い合わせ添付の関連36テストが成功。Black・isort・Flake8・差分検査も成功した。自己レビューでは所有者照合・エラー時の処理・既存のVaryとの共存を確認し、未修正の指摘はない。全体CIはpush後に別途確認する。表示文言・DB・実データ・Secrets・権限付与・AWS・費用は変更していない。アプリは未配備。修正のrevertは可能だが、キャッシュ禁止を取り除くため、実環境の復旧は認可と非公開応答を維持する修正を優先する。
