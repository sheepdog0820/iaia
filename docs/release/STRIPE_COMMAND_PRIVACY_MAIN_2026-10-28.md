# Stripe運用コマンドの情報保護（2026-10-28）

PR #18のf5169af6を基点に、既知6828f209の対象差分を分離する。remote check、テスト商品作成、検証記録のエラー・SDKログから応答本文や例外の原因が出る問題を修正する。対外送信を伴わない合成fixtureだけで再現・検証する。

## 変更と範囲

- Stripe例外は認証・権限・通信・呼び出し制限・一般APIという固定分類と、有効な整数のHTTPステータスだけを出す。request ID・code・本文・キーを出さず、元例外はメモリ内で改変しない。成功扱いや無条件の再実行を避ける日本語案内にする。
- コマンドの同期処理中だけContextVarでSDKログのmsg/args/例外/stackを除く。入れ子や例外後も元の文脈へ戻し、別スレッドや通常リクエストのログへ範囲を拡張しない。Sentryの全経路監査を終えたという意味ではない。
- 固定SDK16.0.1の`_util.log_debug/log_info`は、`stripe.log`やimport時の`STRIPE_LOG`が有効だと標準エラーへ直接出力する。ロガーフィルターで捕まらないため、詳細出力が有効ならクライアント作成/API送信前に停止する。SDKのグローバル設定自体は変更しない。
- 予期しない例外は固定の日本語要約にし、検証記録にも生の例外文字列を保存しない。既存の設定検証メッセージは保持し、その原因例外のtracebackを表示しない。
- テストモードでないProduct応答の無効化処理が失敗した場合に、無効化できたと報告する既存finallyを解消する。Price作成へは進まず、状態の照合を案内する。実Productの作成・無効化は行わない。
