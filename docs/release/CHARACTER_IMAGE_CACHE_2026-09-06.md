# キャラクター画像の保存・削除と一覧キャッシュ

## 確認した問題と修正

6版・7版の作成フォームへ合成PNGを5枚添付し、保存・編集・画像の読み込み・上限超過の拒否・削除・再読み込みまでのブラウザテストを追加した。

修正前はFirefoxの6版で、削除直後に4枚となった画像が再読み込み後に5枚へ戻って表示された。削除APIは204を返していた。保存したトレースでは画像一覧GETにキャッシュ抑止ヘッダーがなく、削除後も同じ古い一覧応答が使われていた。6版・7版の一覧APIにキャッシュ抑止を要求する回帰テストも修正前に失敗した。

`CharacterImageViewSet` のdispatchへDjangoの `never_cache` を適用し、一覧・詳細・認可エラーを含む応答へ `private, no-store, no-cache, max-age=0` を付ける。既存のグループAPIと同じ方針を使う。画像ファイルの配信キャッシュやストレージ設定、DBスキーマ、認可条件は変更しない。匿名で非公開キャラクターを参照した場合の404も維持する。

## 検証と範囲

- 関連APIの44テストに合格（46.567秒）。両版の一覧ヘッダー、匿名エラー、画像操作の既存テストを含む。
- 無料・有料それぞれの5枚上限の既存APIテスト2件にも合格（3.072秒）。
- ブラウザテストでは無料ユーザーの5枚添付、全画像の読み込み、編集後も5枚維持、6枚目の選択拒否、削除後4枚と再読み込みを確認する。
- 修正後は3ブラウザ×2版の6ケースに合格（56.2秒、再試行・スキップなし）。Python変更ファイルのBlack・isortにも合格。

初回のブラウザ検証はファイル一覧オブジェクトの比較方法が不適切だったため途中停止し、ファイル数の確認へ修正した。その後の実行で上記キャッシュ問題を検出した。APIの匿名アクセス期待値も、現行の秘匿方針に合わせ403想定から404へ修正した。これらのテスト側の誤りをアプリの不具合とは扱わない。

`tableno-browser:playwright-1.63` に現在の対象ビュー・テスト・ベーステンプレート・Axios・Playwright設定を重ねた使い捨てコンテナーを使用し、DBと画像はコンテナー内の合成データに限定した。実サービスのS3・CloudFront確認を示すものではない。

証拠: `tmp/character-images-green.log`（修正前）、`tmp/character-image-cache-red.trace.zip`、`tmp/character-image-cache-red.log`、`tmp/character-image-cache-green.log`、`tmp/character-image-quota.log`、`tmp/character-images-final.log`、`tmp/character-create-save-output/results.json`（最新実行）。

## 残る確認と復旧

画像透過の実サービス処理、既存の5枚超過データ、有料失効、実ストレージのアクセス制御については各受け入れ条件の確認が別途必要。今回の変更だけで正式公開可能とは判断しない。復旧は修正のrevertで行い、データ復元やマイグレーションは不要。
