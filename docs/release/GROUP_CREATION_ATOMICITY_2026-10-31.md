# グループ作成と作成者の管理者登録の一貫性（2026-10-31）

グループ作成APIは、Groupの保存後に作成者の管理者メンバーシップを保存していた。この2つの保存をまとめるtransactionがなく、管理者登録前の例外で500を返しても、グループだけが残ることを合成データで確認した。再現試験は1件失敗・正常作成1件成功で、失敗記録を保持している。

`perform_create`を`transaction.atomic`で囲み、グループと作成者の管理者登録を同じtransactionで保存する。管理者登録中の例外ではグループもロールバックし、再試行時に正常なグループを1件だけ作成できることを確認する。正常な作成では作成者のIDと管理者メンバーシップ1件を保持する。

これは保存途中の失敗に対する一貫性の修正であり、グループ所有権移譲・課金・新しい権限の追加ではない。モデルや移行ファイルも変更しない。外部通知や共有環境での実ユーザーデータ変更は行っていない。

新規API回帰2件は、管理者登録の例外注入によるグループの取消と同じ入力の再試行、および正常作成時の作成者/管理者の一致を確認する。[メンバーID検証](GROUP_MEMBER_INPUT_VALIDATION_2026-10-31.md)と既存のグループ・招待・キャッシュ試験を合わせ、SQLite66件・55 subtests、隔離PostgreSQL18.3では招待の並行処理も含む69件・55 subtestsが成功、省略0。2件の修正を合わせた変更実行文28件・分岐arc18件は全実行した。通常配布物と最終headのCIの結果は、固定head/imageとともにDraft PRへ記録する。
