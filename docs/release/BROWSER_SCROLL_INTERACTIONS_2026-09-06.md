# ブラウザ操作前のスクロール完了

## 再現と原因

YouTube並べ替えテストにドラッグイベントの座標と動画行の矩形を記録し、WebKitで5回実行した。2成功・3失敗（うち1件は保存要求なしのタイムアウト）。失敗例では、ドラッグ開始時の `scrollY=1060` が `dragover` 時に989へ変わった。末尾の行の上端も422pxから493pxへ動き、固定されたポインター座標508pxは行の下半分から上半分になった。この座標に応じて画面は途中への挿入を行い、APIにはその順序が送られた。

別の失敗でもドラッグ開始から終了までスクロールが継続し、行の位置が動いた。保存APIが期待順序を別の順序に書き換えた証拠はない。元のトレースでは動画8→1番、7→2番、9→3番の要求が送られ、すべて200で完了した。

診断ソース `tmp/prepare-youtube-drag-probe.py`、結果 `tmp/youtube-drag-probe-output/results.json`、ログ `tmp/youtube-drag-probe.log`、復元イベント `tmp/youtube-drag-events.txt` を保持する。

## 変更

`static/css/arkham_modern.css` の `:root` に `scroll-behavior: auto` を指定し、Bootstrapが全画面へ設定する滑らかな自動スクロールを上書きする。ブラウザやAPIが操作対象を表示する際のスクロールを即時にし、位置が決まった後にクリックやドラッグできる状態にする。ボタン・カードの演出や、セッション開催日の選択箇所へ明示的に `behavior: 'smooth'` で移動する処理は変更しない。ページ内アンカーへの通常の移動も即時になる。

元のGoogle失敗ではクリック後にスクロールが続いていたが、押下・解放の対象要素は未記録であり、YouTubeと同一原因とは断定しない。既存の通常クリックで設定保存・エラー表示・再保存・二重送信防止を検証する。[Google診断記録](DEV_LOGIN_READINESS_2026-09-06.md)も参照。

YouTube・Googleの操作テストは変更せず、通常のドラッグ・クリック、保存要求待機、期待値・再読み込み後の確認を維持する。再クリックやテストの再試行、強制クリックは追加しない。保存処理・API・権限・DBスキーマ・課金への変更はない。復旧はCSS変更のrevertで可能。

## 検証

最初にテスト側だけで事前スクロールを即時にする診断を行ったが、3ブラウザ合計15回で14成功・WebKit1失敗（1.3分）。失敗時もドラッグ開始時のscrollY=1031から954へ変わっていた。事前位置決めだけでは不十分なため、そのテスト変更は取り消した。結果は `tmp/youtube-drag-fixed-output/results.json` に保存する。

CSS修正後のドラッグ診断を3ブラウザ各5回、続いて実ファイルのGoogle設定・YouTube・画面スクリプト検証を3ブラウザで実行する。どちらも再試行0、使い捨てコンテナー内の空のSQLiteと合成ユーザーを使用する。結果は `tmp/youtube-drag-auto-output/results.json` と `tmp/interaction-validation-output/results.json` に保存する。

CSS修正後のドラッグ診断は15件すべて成功（1.3分、終了0）。Chromium・Firefox・WebKit各5回で、並べ替えと再読み込み後の順序を確認した。未修正テストを使うため、テストだけの事前位置調整で得た結果とは区別する。

実ファイルの関連検証も30件すべて成功（1.8分、終了0、再試行なし）。Googleの権限不足・認証失効・403・サーバー異常・通信異常・成功・保存中の二重送信防止、YouTubeのドラッグ保存と再読み込み、主要画面のスクリプト動作を3ブラウザで確認した。

共通CSSおよび別途変更した開発ログイン補助処理の影響を確認するため、全186件のブラウザ検証を `tmp/run-interaction-full-validation.ps1` で実行する。全体結果は `tmp/interaction-full-validation-output/results.json`、進行ログは `tmp/interaction-full-validation.log` に保存する。対象検証の成功だけで全体合格とはしない。

全体実行は185成功・1失敗（16.2分）。Google保存とYouTube並べ替えは3ブラウザで成功した。失敗したFirefoxの6版シナリオからのセッション作成は、タイトルが空のままで保存要求が発生しなかった。後続の入力準備の修正と対象6件の成功は [モーダル検証記録](SCENARIO_MODAL_READINESS_2026-09-06.md) に分けて記録する。更新後の全体CIは別途確認する。
