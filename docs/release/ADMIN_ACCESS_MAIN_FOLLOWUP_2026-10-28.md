# 管理画面の有料権限操作・監査の整合性（2026-10-28）

## 対象と問題

正式公開はNo-Goを維持する。運営コード・権限再照合の[Draft PR #10](https://github.com/sheepdog0820/iaia/pull/10)のhead `e09710f331909598cf8b839c2de044e6fbac3e7a` を基点に、別ブランチ `codex/admin-premium-followups-20261028` で管理者操作を追加修正した。保留中の大きな後続全体は取り込まず、既知の `897e73f0` から製品差分と回帰試験だけを選んだ。

対象は管理画面の「プレミアム権限を停止」「失効状態を解除して再同期」「返金/チャージバック検知を確認済みにする」。従来は一覧取得時の古い課金状態・権限・検知日時を使い、Webhook等の更新を待たなかった。また、監査保存の失敗時に権限や検知状態だけが変更される問題があった。実Stripeでの返金操作や購読解約を追加する修正ではない。

## 修正と利用者への影響

- 選択したIDを主キー順に取り出し、各課金行を `select_for_update()` でロックした後に現在の課金状態・ユーザーを読む。Checkout/Webhook/運営コード/再照合と同じ課金行を直列化の基準にする。
- ロック取得前のユーザーの事前読み込みを避ける。削除済み行を除き、確認済みになった返金等の検知を再処理しない。復旧処理でキャンセル済み購読を古い状態から有効化しない。
- 権限/検知の変更と監査を一件ごとのtransactionに入れる。失敗した一件は双方をrollbackし、成功通知を出さない。複数件の操作で先に処理済みの行を一律に戻す契約へは変更しない。
- 明示的な停止/復旧を繰り返した場合の監査、手動付与を優先する既存の復旧方針、actor・課金行ID・最新の検知日時やsource、日本語の管理者通知を保持する。権限判定の方針・料金は変えない。
- PostgreSQLのCI対象に新しい回帰ファイルを明示追加する。AWS反映や新しい常設ジョブは追加しない。

一般利用者の操作やUIは変更しない。Webhook等と競合する管理者操作は待機後の状態を使い、監査が残らない権限変更を避ける。管理画面の他の編集経路や手動コマンドは別の後続修正であり、この3操作だけで全競合が解消したとは扱わない。

## 検証

Python 3.11.18 / Django 5.2.17 / PostgreSQL 18.3、現在の固定依存で検証した。ゴール専用labelを持つローカルPostgreSQLとinternal networkを毎回照合し、公開ポート・実データ・外部通信のない使い捨てDBだけを使用した。

修正前は17失敗・5成功・3 subtests成功（失敗数には6件のsubtest失敗を含む）。古い購読・検知・source、削除済み行、監査失敗の部分保存と、共有行ロックを待たない3経路を再現した。修正後は **16テスト・9 subtests成功、省略なし**。同時処理は実PostgreSQLの別接続・実行SQLでFOR UPDATEの待機を確認し、単なるmockのロック有無やSQLiteだけで判断していない。

対象のBlack/isort整形確認、Flake8、Banditは成功。製品の追加/変更実行文 **33/33** を通過した。対象試験だけでのadmin全体の網羅率は約49%であり、ファイル全体100%とはしない。新しいアプリUI文言はなく、既存の日本語通知を回帰試験の完全一致でも確認する。

証跡はGit管理外 `tmp/admin-access-pg-red.log`、`tmp/admin-access-pg-green.log`、`tmp/admin-access-pg-coverage/coverage.json`、`tmp/verify_admin_changed_coverage.py`。既存の課金・退会・運営コード・再照合と併せた試験、SQLite、通常配布物と最終CIは後続の記録で明示する。

整形確認後、既存の課金・同時処理・退会・運営コード・失効・再照合・有料機能を含む8ファイルの **269テスト・41 subtestsが実PostgreSQLで成功、省略なし**。追加/変更実行文は33/33のまま、admin全体は約83%である。SQLiteでも13テスト・9 subtests成功、行ロックが必要な3テストのみ意図して省略し、同じ3テストはPostgreSQLで成功した。証跡は `tmp/admin-access-pg-broad.log`、`tmp/admin-access-sqlite.log` に保持する。実Stripeの操作・通信は行っていない。通常配布物と最終CIはまだこの結果に含めない。

## 承認境界と復旧

現時点で共有DB・実ユーザー権限・実Stripe・実AWSを変更していない。DBスキーマ/移行、Secrets/IAM/OAuth、課金/返金、常設資源・継続費用、外部ユーザー通知の変更はない。コードの修正・隔離検証・作業ブランチへの通常push・Draft PRまでを進め、先行PRのマージ後の差分と最終CIを固定してmainへの追加マージを別途承認してもらう。

復旧は対象コミットのrevert PRで可能。ただし元の競合・監査の部分保存を再導入するため、単なる取り消しを正式公開の合格条件にはしない。実AWSの受け入れ、有料必須ゲート、外部連携・OS監査・性能・復旧等の未完了は維持する。
