# キャラクター画像削除の保存先障害と再試行（2026-10-31）

## 問題と修正

キャラクター画像の削除中にファイルI/O、SDK接続、S3応答が失敗すると、従来は500になっていた。6版・7版の主画像について3種の障害、追加画像についてI/O障害を合成し、計8サブケースで再現した。実S3や実ユーザー画像の削除は実行していない。

保存先の`OSError`・`BotoCoreError`・`ClientError`を、既存の`MediaDeletionUnavailable`の日本語503応答に変換する。例外本文・接続先・応答内容は返さず、ログは画像IDと例外型のみとする。`save=False`で保存先の削除を行い、成功する前にファイル参照を空欄として保存しない。

例外は[先行の画像変更トランザクション](CHARACTER_IMAGE_WRITE_SERIALIZATION_2026-10-31.md)の外へ伝え、削除前に変更した主画像フラグもロールバックする。失敗後はレコード・ファイル参照・主画像設定を保持し、保存先が復旧した後に同じ要求を再試行できる。ファイルが既にない場合のレコード削除と、所有者以外の拒否も維持する。

## 検証と適用範囲

修正前の隔離PostgreSQLでは上記8サブケースが500を検出した。修正後の本番設定PostgreSQLでは4テスト・12サブケースが成功し、失敗時のDB値・画像bytesの保持、復旧後の204と主画像引継ぎ、応答・捕捉ログへの診断文の不在、第三者からの保存先操作の不実行、ファイル欠落時の後片付けを確認した。

障害は実ファイルを使う保存先のdelete呼び出しで注入し、DB処理をモックしていない。SDKの例外を合成した検査であり、実AWS認証・S3応答・ネットワーク切断や、あらゆる保存先例外の検証ではない。保存先が削除を受理した後に応答だけ失われる場合、実ファイルの保持は保証しない。後続DB処理に失敗した場合のファイル復元や、DBとストレージの分散トランザクションを実装したものでもない。共有DB/実画像の修復は行わない。

関連テスト・通常配布物・最終CIの結果はPRで別途記録する。既存のPG CIにこの回帰テストを加える。新しいデプロイ処理や外部接続先は追加しない。新規表示文言は既存の日本語再試行メッセージを再利用し、応答のキャッシュ禁止も検査する。
