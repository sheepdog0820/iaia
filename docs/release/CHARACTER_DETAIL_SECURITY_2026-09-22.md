# キャラクター詳細の文字列表示保護

## 修正範囲

技能名（本文・aria-label）、装備名・ダメージ・射程・説明、6版固有情報、プレイ履歴のタイトル・作者・システム名・メモを既存のHTMLエスケープに統一した。数値/IDの型付きAPI契約と既存の日本語ラベルを維持する。textContentを使う技能選択肢はエスケープ不要で、変更しない。

## 検証

- 修正前、6版/7版の技能名に挿入したタグが文字列として保持されず、Chromiumの2テストが失敗した（RED）。
- 修正後、詳細・成長・一覧の3ブラウザー15テスト成功。引用符・HTMLタグ・イベント属性・アンパサンドが文字列として表示され、画像要素・イベントを生成しないこと、技能合計のaria-labelを確認。
- 関連静的テスト46件成功。差分・UTF-8/LF・日本語UI文言を確認し、変更範囲の自己レビューで追加指摘なし。
- 試験用キャラクターはローカルで作成しfinallyで削除。API応答中の表示値のみをモックしており、保存から表示までの全経路を証明するものではない。

## 新たに確認した未完了事項

探索者履歴の `loadPlayHistory` は `character.user` を条件にするが、現行 `CharacterSheetSerializer.Meta.fields` に `user` がない。このため実API応答では取得処理が開始されない。表示セキュリティのテストだけは `user` をモックして旧表示経路を実行する。履歴が実機能として動くという証拠にはしない。

履歴APIは利用者全体の履歴を返すため、単に条件を削除する修正は行っていない。キャラクターとの関連付け、所有者/共有閲覧時の表示範囲と権限を確認し、別の回帰テスト付きで修復する必要がある。F03/F04は未完了。
