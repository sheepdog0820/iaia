# 契約が終了していないアカウントの退会防止

## 問題と修正

退会処理はプレミアム権限の有効状態でStripe契約の有無を判断していた。支払遅延・未払い・一時停止・初回決済未完了、返金等による権限停止中に、契約が残っていてもアプリのアカウントを削除できた。契約の管理先を失い、課金が継続する危険がある。

購読IDが存在する場合は、ローカルに記録した契約状態が `canceled` または `incomplete_expired` の場合だけ退会を許可する。空欄・未知の状態も終了扱いにしない。既存の顧客IDのみのactive/trialing記録も保護し、権限停止日時で退会可否を変えない。購読のない無料・手動付与アカウントの退会は維持する。

Stripeでは支払失敗や権限停止と契約終了は異なる。[公式ライフサイクル資料](https://docs.stripe.com/billing/subscriptions/overview)を確認した。画面と拒否メッセージを日本語で修正し、期間末解約は契約終了後に退会できると明記した。即時解約や返金を自動実行する変更ではない。

## 検証

- 最初の5回帰テストで8ケースの失敗を確認した。文言・顧客IDのみの権限停止ケースも追加して、最終的な回帰テストは6件。
- 回帰・認証・課金の226テスト成功（4.833秒、使い捨てSQLite）。拒否時の利用者保持、期間末解約中の拒否、終了済み契約・無料アカウントの削除を確認。
- テンプレートをDjango Clientでレンダリングし、日本語の警告と課金管理への導線を確認した。ブラウザーによる表示・操作確認は未実施。
- coverageで変更した退会判定関数の未実行行は0。全分岐・並行処理の網羅を意味しない。
- Black/isort、flake8、Bandit、差分検査に合格。Banditは既存テストの不要なnosec注釈について警告したが、脆弱性指摘はなかった。

## 残タスクと反映

この修正はローカルに購読が記録されている状態の退会判定を対象とする。Checkoutを開いたままの退会、Webhook未着・状態遅延、退会と購入の同時処理、実Stripeでの退会組合せは未検証で、課金正式公開の残タスクとして維持する。ローカル記録だけでStripe全体に契約が存在しないとは証明できない。

変更は候補99acd8caから分離した `codex/stripe-deletion-guard-20260919` にある。99acd8caのCI成功を、この修正のCI成功とは扱わない。この問題が判明したため、課金を有効化する公開候補には本修正と残タスクの検証が必要。main/AWSの承認対象を無断で差し替えない。

追加マイグレーション、実データ・Secrets・料金・継続費用への変更なし。実Stripeの更新操作も行っていない。切戻しはコミットのrevertで可能だが、課金契約がある利用者の退会を許してしまうため、課金・退会を制限したうえで判断する。正式公開は引き続きNo-Go。
