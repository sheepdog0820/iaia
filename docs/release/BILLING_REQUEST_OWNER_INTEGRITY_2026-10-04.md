# 購入・顧客作成・Portalのリクエスト所有者整合性

## 対象と判断

正式公開は **No-Go** を維持する。基準は `839e15009a7bec34ef05b654f74e604e2efd48d0`、専用ブランチは `codex/billing-request-owner-integrity-20261004`。[課金レコード管理操作の保護方針](SUBSCRIPTION_OWNERSHIP_POLICY_2026-10-04.md)の回答を待つ間、独立したリクエスト実行時の整合性を修正した。管理者の追加・編集・削除・所有者変更の可否は今回変更しない。

現行処理は、利用者から取得した課金レコードを主キーだけで再取得しており、ロック取得時に所有者が変わっても処理を続けた。Checkoutは取得時の顧客IDで作成する一方、再取得後の顧客IDで契約・旧セッションを検索した。また、保存済みの顧客作成・購入リクエストを現在の所有者と照合せず再実行し、PortalはAPI呼び出し中の行ロックを保持していなかった。

## 修正と利用者への影響

- 顧客作成の保存・実行の両段階、Checkoutの全ループ、Portalで、共有課金行をロックして現在の `user_id` と依頼者のIDを照合する。
- CheckoutとPortalは、取得時の顧客IDとロック後の顧客IDが一致し、空でないことを確認する。変化した場合は別の顧客へ自動切替せず拒否する。
- 保存済みリクエストの `metadata.user_id`、Checkoutの `customer` / `client_reference_id` / `subscription_data.metadata.user_id` を照合する。欠落・不正な構造・不一致は、Stripeの取得・作成・失効やリクエストの更新・削除より前に拒否する。
- 顧客作成・Checkoutの既存ロックを維持し、Portalも外部API呼び出し終了までロックする。失敗時に別の所有者へ付け替えたり、再試行キーを破棄・再発行したりしない。
- 通常の二重クリック、応答消失時の同一キー・元プロフィールでの再試行、同一所有者の月額/年額変更、旧セッション失効、既存契約拒否、23時間経過時の確認案内は維持する。権限付与・Webhook・料金・税設定は変更しない。

対応を確認できない場合の新しいAPIエラーは、HTTP 400の「課金情報の対応を確認できません。お問い合わせ窓口へご連絡ください。」。実API Clientで両エンドポイントの日本語・URLを返さないことを確認した。既存の英語エラー全体の改訂は対象外。テンプレート・JavaScript・表示レイアウトは変更していないため、今回のブラウザー描画試験は未実施。

## 残課題・反映境界・復旧

取得開始前から誤った顧客IDが結び付いた行、重複ID、過去の所有者付け替え/削除、再試行記録のない旧顧客の実所有者は、この照合だけで検知・修復できない。管理者による付け替え/削除後の権限・配送・Webhook等の別経路は[回答待ちの運用選択](SUBSCRIPTION_OWNERSHIP_POLICY_2026-10-04.md)として残す。全所有者境界の合格ではない。Portalのネットワーク待ちを含むロック競合・性能は実環境で未検証。

Stripeスキルは最新SDK/API・StripeClient・制限付きキーを推奨するが、今回は現行仕様維持の整合性修正に限定し、SDK/API/認証方式を更新しない。長期運用用RAKは最小権限でSecrets Managerへ保存する既存案を維持し、作成・Secrets更新は未実施。税込価格の税設定は変更せず、販売対象・税務/Stripe Tax・登録の確認も公開前の未完了条件として残す。

今回main/AWS/共有DB/実ユーザーデータ/Secrets/IAM/課金有効化/常設容量/継続費用を変更していない。別途読み取り確認済みのmainは8567f49f、AWSは定義54・1/1/0・HEALTHY・配布digest一致・DB/cache正常。固定反映案6b6c570cと、完了したfavicon承認の対象を拡張しない。元checkoutの未コミットハンドアウト差分は保持する。pushはCIのみでAWS反映を起動しない。

復旧は今回コミットのrevertだが、再現した不一致実行経路が戻るため応急対応と明示し、修正を保持したfix-forwardを検討する。DB/Stripeの変更・逆移行は不要で、実データの自動修復は行わない。正式公開No-Go、B03/B04/Q04等の実運用・権限全経路・OS/外部連携/性能/復旧不足を維持する。
