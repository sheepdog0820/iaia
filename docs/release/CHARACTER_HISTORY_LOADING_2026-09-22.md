# 探索者履歴の取得修復

## 原因と修正

詳細画面はAPIに存在しない `character.user` を条件にして取得を中断していた。また、取得先は利用者全体の履歴であり、条件だけを削除すると別探索者の履歴まで表示する。

- `GET /api/scenarios/history/?character_sheet=<id>` を追加し、所有者本人の履歴を、本人のセッション参加情報に指定された探索者IDで絞る。
- パラメーター省略時の本人全履歴は維持する。空・不正・存在しないID、他人の探索者は404、匿名は401。他人の履歴・メモへのアクセスは拡張しない。
- 所有者の詳細画面だけに探索者履歴タブを表示し、探索者ID付きAPIを呼ぶ。公開/共有閲覧者には表示しない。
- 空表示は「この探索者を設定したセッションのプレイ履歴はありません。」。CoC 6版/7版のシステム名を日本語表示する。
- 履歴を新規生成・再関連付けする変更ではない。セッション未指定の手動履歴や、別探索者/別世代を指定した参加履歴は含めない。参加情報の現在の紐付けを参照し、過去の変更前の探索者を復元するものではない。

## 検証

- 修正前は探索者による絞り込み・不正ID拒否・所有者以外の非表示が失敗（RED）。
- 関連API/キャッシュ10テスト成功。対象一致、別探索者・無関係履歴除外、参加者の一致、所有者/他人/匿名、公開探索者への他人の照会拒否を確認。
- シナリオ機能全体と関連UI静的テストの計128件成功（65.243秒）。Black/isort・差分検査成功。日本語文言と自己レビューで本修正範囲の追加指摘なし。
- 追加8テストによるcoverage計測で、変更したget_queryset処理（369〜383行）の実行可能13行すべてを実行。これは変更箇所の行カバレッジであり、viewsモジュール全体の100%を意味しない。
- 6版/7版×Chromium/Firefox/WebKitの6テスト成功（19.0秒）。実APIの空履歴をブラウザーで取得し、存在しないuserフィールドのモックを削除した。非空履歴のHTML保護は応答をモックした表示試験、データ紐付けはDjango API試験で確認している。保存から非空表示までのブラウザー一貫試験は未実施。

## 後続の保存・表示一貫試験

アプリ候補 `d0a73eae` を対象に、`character-history-persistence.spec.ts` で6版/7版×3ブラウザーの計6件が成功（27.2秒、再試行なし）。上記の「保存から非空表示までのブラウザー一貫試験は未実施」は、この限定条件で解消した。

- モックなし。ブラウザー内から実APIで一時グループ・非公開シナリオ・探索者2名・セッション2件・参加情報・履歴2件を保存。
- 各探索者の履歴IDが正しく分離され、別探索者のメモが混入しない。ページ再読み込み後も一致。
- シナリオ名/履歴メモに保存したタグ・イベント属性を文字として表示し、画像要素生成0・イベント実行0。システム名は6版/7版を日本語で表示。
- finallyで作成した履歴・セッション・探索者・シナリオ・グループを逆順に削除し、削除失敗0。初回の試験準備はKP/GM指定不足で400になったが、仕様どおりas_gmを指定して解消し、一時データは削除済み。
- ローカルadminのdev-loginを使用。通常登録利用者での作成フォーム操作、他人/匿名のブラウザー経路、実AWS全フローの証明ではない。権限拒否は前述のDjango API/HTMLテストの証拠を維持する。
- この追加はテスト/文書のみ。差分・UTF-8/LF・日本語表示・自己レビューを確認し、アプリ全体テストの再実行は行わない。候補CI `35700904425` は確認時点で実行中。
