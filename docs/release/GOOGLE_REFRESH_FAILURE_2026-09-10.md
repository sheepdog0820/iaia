# Google認可更新失敗時のジョブ終了

## 問題と修正

期限切れのGoogleトークンを更新する処理で、google-authのRefreshError（更新拒否等）とTransportError（通信失敗）が呼出し側へそのまま伝わっていた。Calendar/Sheetsのworkerはこの例外を処理せず、ジョブをRUNNINGへ変更した後に終了してしまうため、利用者には処理中のまま残った。

この2種類をトークン取得失敗として既存のworkerの失敗経路に渡す。ジョブはFAILED・終了時刻ありとなり、Calendarの同期記録もFAILEDになる。利用者向けの固定文言は「Google認可の更新に失敗しました。時間をおいて再試行し、解消しない場合はGoogleを再連携してください。」とした。

外部サービス由来の生のエラー文はジョブに保存せず、例外チェーンにも引き継がない。失敗した更新結果で保存済みトークンを書き換えない。通信エラーを自動再試行する変更ではなく、失敗を明示して既存の手動再試行につなぐ変更である。

## 検証

配布イメージ595a390aに新テストだけを読み込み、RefreshError/TransportErrorとCalendar/Sheetsの4組合せでジョブがRUNNINGのまま残ることを再現した。修正ソースも読み込んだ場合は関連28テストすべて成功。

- 4組合せともジョブがFAILED、終了時刻が保存され、日本語の固定メッセージとなる。
- Calendarの同期状態とエラーも更新される。
- 元のアクセストークン・更新用トークン・有効期限は維持される。
- Calendar/Sheetsの書き込みAPIを呼ばない。
- 既存の認可更新成功ケース、再試行の権限/対象維持ケースも成功。

外部通信を遮断した使い捨てコンテナ・メモリDB・ダミートークンと認可更新モックを使用。実Googleへの認可更新や送信は行っていない。コンテナは終了時削除。証跡はGit管理外の `tmp/google-refresh-failure-red.log`、`tmp/google-refresh-failure-green.log`。

Black/isort/flake8、差分、日本語メッセージを確認。DB移行・共有データ変更・権限/Secrets・課金変更なし。既に処理中になっている過去ジョブの一括修復は行わない。全体CIと通常イメージへの組込み検証・開発AWS反映は未完了。実Googleの認可失効/復旧試験は別の残条件である。
