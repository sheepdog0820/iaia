# 登録時の入力フォーカス保護

2026-09-08、外部フォントの自己配信を検証中、WebKitの通常登録でパスワード入力が途中で止まった。traceの入力イベントでは、入力中のpassword1からusernameへ486ms時点でフォーカスが移り、その後の文字がusernameへ入っていた。単なる処理時間超過として扱わない。

CustomSignUpFormがDjango UserCreationFormから継承したusernameのautofocusを除去する。初期カーソルの自動配置をやめ、利用者が選択した入力欄を保持する。ログインフォーム、登録の認証・検証・保存処理は変更しない。パスワードの自動再入力やテスト再試行で失敗を隠す対応はしない。

回帰テストは修正前にusernameのautofocus=Trueで失敗し、修正後に成功。フォント変更と合わせた外部通信なしの隔離環境で、匿名参加から通常登録・ゲスト引継ぎまでChromium/Firefox/WebKitの3件が再試行0、既定30秒のまま成功（51.6秒）。静的配信2件とフォント1件も成功した。証跡はGit管理外のtmp/local-fonts-run.log（初回失敗）、tmp/local-fonts-fixed-run.log（修正後）。

認証の既存30テストも隔離SQLiteで成功（20.955秒）。Black/isort、差分・UTF-8/LFと自己レビューに問題なし。表示文言の変更はない。

この修正は観測したフォーカス移動の原因候補を除去するものであり、過去のFirefoxのページ読み込みタイムアウトも同じ原因だったとは断定しない。CI全体と実Safariでの検証は別途必要。実データ・DB構造・Secrets・料金・権限への変更はない。復旧はこのフォームと回帰テストのコミットを戻す。
