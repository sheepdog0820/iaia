# キャラクター作成画面の保存確認（2026-09-06）

## 対象と発見した不具合

正式公開の受け入れ条件 F04 について、6版・7版の作成フォームから保存し、編集画面を開き直す回帰テストを追加した。既存のシナリオ連携テストは作成画面への遷移までで、フォーム保存を検証していなかった。

6版では読み仮名を入力しても作成APIが保存対象へ渡さず、再表示時に空になった。Chromium・Firefox・WebKit のすべてで再現した。7版は同じ操作に合格した。6版の作成APIへ `name_kana` の保存を追加した。未指定時は従来どおり空文字とする。

## 検証

- API回帰テスト: 修正前は JSON・multipart の両方で保存値が空になり失敗。修正後は `accounts.test_character_sheet_api` の41テストに合格（23.917秒）。
- ブラウザテスト: 一般ユーザー相当の隔離テストアカウントで名前・読み仮名・年齢・8能力値を画面から入力し、保存後の編集画面とAPIで確認する。HP・MP、および7版の独立した幸運値も確認する。
- 修正後は3ブラウザ×2版の6ケースが合格（30.3秒、再試行・スキップなし）。
- Pythonの変更2ファイルは Black・isort に合格。画面の文言・レイアウト変更はない。

使い捨てコンテナー内のSQLiteと合成ユーザーを使用し、共有環境のデータには触れていない。ブラウザ環境は `tableno-browser:playwright-1.63` に現在のベーステンプレート・Axios・設定・対象テストを重ね、修正後の確認では対象ビューも重ねた。API確認も現在の対象ビューとテストを重ねて実行した。

証拠は `tmp/character-kana-red.log`、`tmp/character-kana-green.log`、`tmp/character-create-save.log`、`tmp/character-create-save-green.log`、`tmp/character-create-save-output/results.json` に保存する。

## 残る範囲と復旧

今回の確認は作成と再読み込みであり、画像・技能編集・バージョン作成・削除を含むF04全体の完了を意味しない。正式公開には最新コミットのCIと他の受け入れ条件の確認も必要。

DBスキーマ・権限・課金・外部通信の変更はない。まだ失われている既存キャラクターの読み仮名を復元する変更ではない。復旧はこの修正のrevertで行え、保存済みの読み仮名を削除する必要はない。
