# キャラクター作成画面の保存確認（2026-09-06）

## 対象と発見した不具合

正式公開の受け入れ条件 F04 について、6版・7版の作成フォームから保存し、編集画面を開き直す回帰テストを追加した。既存のシナリオ連携テストは作成画面への遷移までで、フォーム保存を検証していなかった。

6版では読み仮名を入力しても作成APIが保存対象へ渡さず、再表示時に空になった。Chromium・Firefox・WebKit のすべてで再現した。7版は同じ操作に合格した。6版の作成APIへ `name_kana` の保存を追加した。未指定時は従来どおり空文字とする。

## 検証

- API回帰テスト: 修正前は JSON・multipart の両方で保存値が空になり失敗。修正後は `accounts.test_character_sheet_api` の41テストに合格（23.917秒）。
- ブラウザテスト: 一般ユーザー相当の隔離テストアカウントで名前・読み仮名・年齢・8能力値を画面から入力し、保存後の編集画面とAPIで確認する。HP・MP、および7版の独立した幸運値も確認する。
- 修正後は3ブラウザ×2版の6ケースが合格（30.3秒、再試行・スキップなし）。
- Pythonの変更2ファイルは Black・isort に合格。画面の文言・レイアウト変更はない。

使い捨てコンテナー内のSQLiteと合成ユーザーを使用し、共有環境のデータには触れていない。ブラウザ環境は `tableno-browser:playwright-1.63` に現在のベーステンプレート・Axios・設定・対象テストを重ね、修正後の確認では対象ビューも重ねた。API確認も現在の対象ビューとテストを重ねて実行した。

証拠は `tmp/character-kana-red.log`、`tmp/character-kana-green.log`、`tmp/character-create-save.log`、`tmp/character-create-save-green.log`、`tmp/character-create-save-output/results.json` に保存する。

## 編集保存の追加確認

作成済みキャラクターの名前・読み仮名・年齢・CON・POWをフォームで変更し、更新後の詳細画面と再読み込みした編集画面、API応答を確認するテストを追加した。CON・POWの変更による最大HP・MPの再計算と、7版の幸運がPOWに連動して上書きされないことも確認対象とする。

初回は7版の詳細URLを版別と想定したため、7版の3ケースが遷移待ちで失敗した。`CharacterDetailRedirectView` とURL定義を確認したところ、現在は両版とも `/accounts/character/6th/<id>/` を使用する共通詳細画面だった。テストを現行ルートへ合わせた。版の保存値の検証はAPI応答で維持する。アプリのルートや表示は変更していない。

実行環境は上記と同じ隔離環境で、証拠は `tmp/character-edit-save.log` と `tmp/character-edit-save-green.log`、`tmp/character-create-save-output/results.json`。後者は最新実行結果で上書きされる。

最終実行は Chromium・Firefox・WebKit × 6版・7版の6ケースに合格（44.1秒、再試行・スキップなし）。テストと文書だけの追加であり、バックエンド全体の再実行は行っていない。

## 技能ポイントの追加確認

「目星」の職業20・趣味10ポイントを作成画面で入力し、保存後の編集画面で一致を確認する。さらに職業30・趣味15へ変更し、再読み込みした編集画面と技能APIの保存値を照合する。6版・7版とも初期値25が維持されることも確認した。

画像操作を含む同じフローで3ブラウザ×2版の6ケースが合格（64.386秒、再試行・スキップなし）。現在の対象ビュー2ファイルを重ねた隔離コンテナーで実行し、証拠は `tmp/character-skills.log` と `tmp/character-create-save-output/results.json`。今回はテスト・文書のみの変更で、バックエンド全体の再実行は行っていない。

この確認は代表技能の通常配分であり、全技能・カスタム技能・上限や全計算方式のブラウザ確認を示すものではない。

## 残る範囲と復旧

今回の確認は作成・基本情報と能力値の編集・再読み込みであり、画像・技能編集・バージョン作成・削除を含むF04全体の完了を意味しない。正式公開には最新コミットのCIと他の受け入れ条件の確認も必要。

DBスキーマ・権限・課金・外部通信の変更はない。まだ失われている既存キャラクターの読み仮名を復元する変更ではない。復旧はこの修正のrevertで行え、保存済みの読み仮名を削除する必要はない。
