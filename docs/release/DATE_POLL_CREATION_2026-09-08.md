# 日程調整の同時作成と保存失敗への対応

2026-09-08、作業ブランチ06b37350からの修正。既存仕様の「同じセッションには未締め切りの日程調整を1件まで」をAPIの同時作成でも維持する。

## 再現と変更

作成前のvalidateでは既存投票・日時・権限を検査していたが、保存時には再確認していなかった。2件が事前検証を通過すると同じセッションに未締め切り投票が2件作成された。また、事前検証後に日時確定や管理者降格があっても保存でき、候補の2件目で例外が起きると投票と候補1件目が残った。新規回帰テストは変更前4失敗/1スキップ。

作成処理をトランザクション化し、関連セッションを主キーでロックして現在の値を取得する。その後に既存のvalidateを再実行し、投票と全候補をまとめて保存する。削除済みの関連セッションは日本語の検証エラーとする。関連セッションを持たない投票も、保存直前の検証と原子的な保存を行う。

## 検証結果

- SQLite: 新規作成テスト・確定・編集権限・高度な日程調整・キャッシュの計44件で39成功/5スキップ（21.852秒）。
- PostgreSQL 16: 同じ44件すべて成功（45.159秒）。スキップされた5件の並行試験も成功。
- 新規の並行試験は別々のAPI接続が両方とも事前検証を通過するまでBarrierで同期し、同時に保存へ進める。201と400が1件ずつ、未締め切り投票1件・候補2件を確認。lock_timeoutは5秒、Barrierは10秒、future待ちは20秒で制限し、再試行で成功扱いにしない。
- 事前検証後の日時確定、管理者降格、セッション削除を拒否。候補保存失敗時は投票と保存済み候補が残らないことを確認。
- 変更したPython2ファイルのBlack/isort/Flake8、差分・日本語メッセージのレビューに成功。削除済みセッションの日本語エラーはテストでも確認。
- 新規test_date_poll_creation.pyをCIのproduction-databaseジョブへ追加。リモートCIの結果はローカル結果とは別に確認する。

既存検証イメージtableno-full:01a52f52に現行schedulesのみを読み取り専用で重ねた対象検証。ENV_FILEは空、資格情報は合成値、PGは専用internalネットワーク内の空DB。共有環境や実ユーザーデータは使用せず、専用PGとネットワークは所有ラベルを確認して削除した。候補全体の再ビルド・全体試験を証明する結果ではない。

## 影響と残条件

スキーマ・Secrets・料金に変更はない。セッションの行ロックは作成処理の間だけ保持する。DB制約の追加ではないため、直接ORM操作や別の作成経路まで一意性を保証するものではない。既存の重複投票の調査・修復、明示的な再開、異なる既存投票から同じセッションへの再確定は未完了。管理ロール変更自体を同じトランザクションでロックする保証でもない。

取り消す場合はこの修正をrevertできるが、重複作成・事前検証後の状態変化の見落とし・保存途中のデータ残存が再発する。正式公開の残条件は[受け入れ表](FORMAL_RELEASE_ACCEPTANCE_MATRIX.md)を参照。
